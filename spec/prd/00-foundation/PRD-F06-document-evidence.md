## 1. Problem Statement

Claims are decided on evidence: photos, estimates, invoices, police reports, medical records, recorded statements, and the policy wording itself. In many systems these are files in a bucket with a filename and a claim number, with no provenance, no chain of custody, and no link between an extracted value and the page it came from. That makes fraud harder to detect, litigation harder to defend, and AI extraction impossible to verify. The platform needs a structured document model with immutable content, provenance, explicit links to business entities, and traceable derived data.

## 2. Goals

1. **Every document has provenance**: who/what submitted it, through which channel, when, from which device/source, with content hash — 100% coverage.
2. **Evidence integrity**: content is immutable and verifiable by hash; redactions and conversions are derived versions, never overwrites.
3. **Traceable extraction**: every value extracted from a document (by AI or human) links to document, page/region, and extractor version.
4. **Access is correct by construction**: document access inherits from linked entities and sensitivity classification; zero unauthorized document views.
5. **Generated documents are reproducible**: any issued policy packet or letter can be regenerated byte-equivalent from template version + data snapshot, or retrieved as issued.

## 3. Non-Goals

- **Enterprise content management for non-insurance records** (HR, contracts with suppliers).
- **Full e-discovery platform.** Supports legal hold and export; review tooling is external.
- **Image forensics research.** Provides hooks (perceptual hash, EXIF) for R03; advanced forensics via vendors (S02).
- **WYSIWYG template design studio.** Templates are authored in a structured format; a rich designer is P2.

## 4. Personas & User Stories

**Claimant / insured**
- As a claimant, I want to upload photos and receipts from my phone and see that they were received so that my claim isn't delayed.

**Adjuster**
- As an adjuster, I want all documents for a claim organized by type and claim line, with extracted key values shown next to the source page, so that I can verify quickly.
- As an adjuster, I want to request a specific document from a party (e.g., repair estimate) and track whether it arrived.

**SIU investigator / litigation counsel**
- As an SIU investigator, I want an evidence chain-of-custody report (submitted by, hash, every access, every derived version) so that evidence holds up in proceedings.
- As litigation counsel, I want documents on a litigated claim placed on legal hold automatically.

**Compliance / records manager**
- As a records manager, I want retention schedules applied by document class and jurisdiction so that we keep what we must and dispose what we may.

**Policy operations**
- As policy ops, I want declarations pages and policy packets generated from approved template versions so that issued documents match filed forms.

**Edge cases**
- An uploaded file is infected → quarantined, uploader told to resubmit, never served.
- The same photo is uploaded on two different claims → flagged to fraud signals (R03).
- A document is uploaded to the wrong claim → re-link with reason; original link history preserved.

## 5. Domain Model & Invariants

| Entity | Key attributes |
|---|---|
| **Document** | id, tenant, document type (configurable taxonomy), title, current version, sensitivity (`PUBLIC`, `INTERNAL`, `PII`, `SENSITIVE_PII`, `PHI`, `PRIVILEGED`), retention class, legal-hold flags, status (`QUARANTINED`, `AVAILABLE`, `REJECTED`, `DISPOSED`) |
| **Document Version** | content hash (SHA-256), storage ref (content-addressed), media type, size, page count, derivation (`ORIGINAL`, `REDACTED`, `CONVERTED`, `THUMBNAIL`, `OCR_TEXT`) + parent version |
| **Provenance** | submitter (`ActorRef`), channel (`PORTAL`, `MOBILE`, `EMAIL`, `API`, `VENDOR_PORTAL`, `SCAN`, `GENERATED`), received-at, original filename, device/app metadata, capture metadata (EXIF time/geo where present), source system ref |
| **Document Link** | document ↔ entity (policy, term, claim, claim line, party, payment order, vendor assignment, invoice, SIU case, submission) with link role (`EVIDENCE`, `ESTIMATE`, `INVOICE`, `CORRESPONDENCE`, `POLICY_FORM`, …), linked-by, linked-at, unlink history |
| **Custody Event** | view, download, share, export, derive, link, unlink, hold, release — actor, time, purpose |
| **Document Request** | requested-from party, requested type, due date, status (`OPEN`, `FULFILLED`, `WAIVED`, `OVERDUE`) |
| **Extraction** | document version, extractor (`AI_AGENT` id+version / `HUMAN` / `OCR` engine), fields (name, value, confidence, page, bounding box/text span), verification status (`UNVERIFIED`, `VERIFIED`, `CORRECTED`), verified-by |
| **Template** | id, type (dec page, policy packet, letter, notice), jurisdiction/product applicability, version, effective period, required data schema, approval |
| **Generated Document Record** | template version, data snapshot hash, render engine version, output document version |

**Invariants**
- INV-F06-1: Content at a storage ref never changes (content addressing; object lock for evidence classes).
- INV-F06-2: A document is servable only in `AVAILABLE` status (post malware scan).
- INV-F06-3: Effective access = union of access to linked entities ∩ sensitivity obligations (PHI requires explicit PHI permission even if claim access exists).
- INV-F06-4: Derived versions reference their parent; originals of evidence documents are never replaced or removed while under hold.
- INV-F06-5: Extraction values used in decisions reference a specific document version and region.
- INV-F06-6: Issued documents (policy packets, regulatory letters) are retained as issued, independent of template changes.

## 6. Requirements

### P0 — Must-have

**F06-P0-01 Upload & ingestion.** Resumable uploads (large files, mobile networks), per-type size/format limits, hash on receipt, malware scan before availability, format normalization (HEIC → JPEG derived version), virus-positive quarantine.
*Acceptance:* Given an upload, when scanning passes, then the document becomes `AVAILABLE` within 30 s p95 and `documents.document.available.v1` is emitted; infected files never become retrievable.

**F06-P0-02 Provenance capture.** Mandatory provenance fields per channel; EXIF/capture metadata preserved in the original and extracted into provenance.

**F06-P0-03 Linking.** Link/unlink with roles and reason; a document can link to multiple entities; history preserved.

**F06-P0-04 Access inheritance & obligations.** Authorization via PDP using linked entities and sensitivity; masking obligations honored in viewers; signed, short-lived download URLs.

**F06-P0-05 Custody & read audit.** All views/downloads/exports recorded (CRC-SEC-012); chain-of-custody report per document.

**F06-P0-06 Classification & retention hooks.** Sensitivity and retention class assigned at ingestion (by type and channel; reclassification audited); legal holds from litigation flag (C02) and R01.

**F06-P0-07 Document requests.** Create requests to parties with due dates and reminders (X04), fulfilled by upload against the request.

**F06-P0-08 Extraction records.** API to attach extractions (from AI02, OCR, human), with verification workflow and correction capture (corrections feed AI02 evals).

**F06-P0-09 Templates & generation.** Versioned, approved, effective-dated templates; generation from data snapshot; record of template version + data hash; issued output stored as a document linked to the entity.
*Acceptance:* Given an issued declarations page, the platform can show the template version and data snapshot used and regenerate an equivalent rendering.

**F06-P0-10 Redaction.** Produce redacted derived versions (manual regions + PII detection assist) for sharing with third parties; originals untouched.

**F06-P0-11 Metadata search.** Find documents by entity, type, date, submitter, status (full-text in S01).

### P1 — Fast follow
- **F06-P1-01** Perceptual hashing and duplicate/near-duplicate image detection across claims → R03 signals.
- **F06-P1-02** E-signature integration (S02) with signed-document evidence (certificate, audit trail).
- **F06-P1-03** Email ingestion: inbound mailbox per claim/policy with attachment extraction and auto-linking suggestions (AI02).
- **F06-P1-04** Bulk export bundles (litigation, regulator) with manifest and hashes.
- **F06-P1-05** Print & mail integration with proof-of-mailing captured as linked evidence (for cancellation/required notices).

### P2 — Future
- **F06-P2-01** Video and audio evidence with transcripts (recorded statements).
- **F06-P2-02** Telematics/IoT data objects as evidence (crash data).
- **F06-P2-03** Visual template designer.

## 7. Interfaces & Events
- APIs: `POST /v1/documents` (initiate upload), `PUT …/content`, `POST /v1/documents/{id}/links`, `GET /v1/documents/{id}` (+ signed URL), `POST /v1/document-requests`, `POST /v1/documents/{id}/extractions`, `POST /v1/generation-jobs`.
- **Events published**: `documents.document.received.v1`, `…available.v1`, `…quarantined.v1`, `…linked.v1`, `…unlinked.v1`, `documents.extraction.recorded.v1`, `…verified.v1`, `documents.request.created.v1`, `…fulfilled.v1`, `…overdue.v1`, `documents.document.generated.v1`, `documents.hold.applied.v1`.
- **Events consumed**: `claims.claim.litigation-flagged.v1` (hold), `privacy.retention.disposal-approved.v1`, `policy.term.issued.v1` (generation jobs).

## 8. AI Integration Points
- AI02 classifies documents and proposes extractions (PROPOSE → verification).
- AI03/AI07 cite document versions and spans (CRC-AI-008); S01 indexes text versions.
- Redaction assist uses PII detection; humans confirm before external sharing.

## 9. Audit, Security & Compliance
- PHI handling: explicit permission, read-audit, minimum necessary display.
- Privileged (attorney-client) documents restricted to litigation roles.
- Retention and disposal executed only by R01 with proof of disposal; evidence classes use object lock.

## 11. Open Questions
- [Engineering] [Blocking] Object storage with object-lock/WORM per region; encryption key hierarchy shared with R01.
- [Legal] [Blocking] Retention classes and holds by document type and jurisdiction.
- [Product] [Non-blocking] Rendering engine for templates (HTML→PDF vs. document-model engine).

## 12. Dependencies & Phasing
- **First**: upload/scan/store/link/access/provenance — needed by C01 and X01–X03.
- **Then**: templates & generation (needed by P02 issuance and X04 letters), extractions (needed by AI02), requests.
- **Parallel**: redaction, perceptual hashing, email ingestion, e-signature.
